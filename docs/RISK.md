# 封控拦截

请求在选槽、出站之前先过一道闸。`/v1` 和 `count_tokens` 共用。拦住就不 hop，不消耗上游额度。管理台入口是「风险审计」（`/console/#/risk`）。

顺序固定，便宜的规则在前，模型在最后，不能调换。

## 五道关

| 顺序 | 关 | 扫什么 | 拦住 |
|------|----|--------|------|
| 1 | 蒸馏 | 收割模板、题目指纹、结构特征 | 默认 403，并封 device |
| 2 | 硬正则 | 用户正文上的类别正则 | 403，不进槽 |
| 3 | 拒答缓存 | 上游拒过的正文、近似正文、已封 device | 503 |
| 4 | 决策模型 | 安全模型逐题打分 | 低于阈值则 403 |
| 5 | 放行出站 | 前面都没拦的请求 | 进入槽位 |

「放行出站」不是第六道闸。它同时列出两类没被闸拦住、但结果仍异常的请求：决策模型打分失败后的放行，以及上游自己的拒答。用来看漏拦。

## 蒸馏

总开关默认开。OpenAI 平台模型整段跳过，不扫针、指纹，也不扫蒸馏类正则。

检测器（针、指纹、结构收割）默认再跳过官方 Claude Code 和 0 注入。这是 `skip_official` / `skip_zero`，面板可关。

硬正则里的 distill 类别不看这两个跳过。关掉硬正则总开关仍然拦这些短语；只有关掉蒸馏总开关才放行。官方客户端和 0 注入仍扫。OpenAI 不扫。

命中返回蒸馏关配置的 HTTP 状态，默认 403，文案默认「不允许蒸馏」，并封这次请求的 device。

单独的思考标签不是蒸馏。要拦的是要求「按该格式作答」的收割模板。

## 硬正则

类别：色情、蒸馏、破解、破限、自定义。蒸馏类见上一节，其余跟硬正则总开关。命中 403，不写入拒答缓存。

附加正则和内置规则一起扫。扫描前默认去掉常见提醒，并展开正文里的 base64；这两项可关。

## 拒答缓存

只记上游真正拒过的正文。硬正则和决策模型自己打回的拦截不进这张缓存，下次仍重新过闸。

三种命中都是 503：

- 精确指纹
- 近似正文（默认相似度 0.9，面板可调）
- 已封禁的 device

## 决策模型

最后一道。把整理后的正文交给配置的安全模型，逐题打分。低于阈值才拦，返回 403。

只有一道题落在阈值下方 0.08 以内时不拦。两道题都低于阈值，或一道题明显更低，仍然拦。同一段正文在去重窗口内复用上一次结论。

模型不可用时默认放行，风险审计里记为「模型故障放行」。关掉失败放行后，模型不可用则拦。401 / 429 / 529 会换下一把密钥再试。

没配模型地址时，这道闸等于没接上，不要当成已经在保护账号。

## 日志

每条请求记下过了哪一关、命中词和规则。升级前没有这条记录的旧日志，在风险审计里显示为「未经关卡」。

被放行的正常请求在「日志」，不在拦截流水里。误伤时收紧或关掉对应的关，不要删槽。这一页上未保存的修改，离开时会丢掉。

## 在面板里改
